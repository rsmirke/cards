# Architecture

This file describes the code **as it is now**. The target layout is in [SPEC.md §2](SPEC.md#2-architecture); update this file whenever a slice changes the structure.

## Workspace

A Cargo workspace (`Cargo.toml`) with two crates. Shared dependency versions, package metadata and lints live in the root `Cargo.toml` (`[workspace.dependencies]`, `[workspace.package]`, `[workspace.lints]`); each crate opts in with `.workspace = true` / `[lints] workspace = true`.

| Crate | Path | Kind | Role |
|---|---|---|---|
| `rappel-core` | `crates/core` | library | All logic. No UI dependency, testable with plain `cargo test`. |
| `rappel` | `crates/app` | binary | GTK4 + libadwaita front end. Talks to core only. |

`third_party/ratex-cairo` is a vendored copy of the `ratex-cairo` crate with `cairo-rs` bumped to 0.22 (ADR 0021, `VENDORED.md` there). It is not a workspace member (`exclude = ["third_party"]`) and is used through `[patch.crates-io]`.

Dependency direction: `rappel` → `rappel-core`, never the reverse. `rappel-core` must not depend on gtk4, glib, gio, libadwaita or anything UI.

### `rappel-core` today

Only what a front end or `examples/` uses is `pub`; everything else is `pub(crate)`, and code that only tests need is `#[cfg(test)]` (e.g. `is_valid_app_id`). Make an item `pub` in the slice that first needs it outside the crate.

- `src/lib.rs`: the app name and ID constants (its tests check `APP_ID` the way `g_application_id_is_valid` does); re-exports `Error` and `Result`.
- `src/test_support.rs` (test builds only): helpers shared by several modules' tests: `T0`, `DAY_MS`, `scheduled`, `answer`, `schedule_table`, `with_suffix`, and `within` (runs hostile input on a 512 KiB stack and fails the test past a time limit; `RAPPEL_TIMINGS=1` prints the time, ADR 0025). Use them instead of a local copy.
- `src/error.rs`: the crate-wide `Error` enum (`thiserror`) and `Result` alias. `Random` boxes its cause so `getrandom` stays out of the API; `rusqlite` and `fsrs` errors stay visible (ADR 0015).
- `src/data_dir.rs`: `resolve_data_dir` (pure; takes a `DataDirEnv` and a `BuildProfile`) and `ensure_data_dir` (creates a directory with mode `0700`). Debug builds refuse the release directory and the pre-rename `cards` one. See ADR 0004 and ADR 0020.
- `src/id.rs`: `IdGen`, strictly increasing `UUIDv7` strings (a 122-bit counter with random low bits; `observe` raises it above an id read from the database). See ADR 0008. `is_uuid_v7` checks ids from outside (an import, ADR 0017).
- `src/time.rs`: `now_ms` (UTC milliseconds), `utc_parts` (calendar fields from milliseconds) and its inverse `utc_ms`.
- `src/domain/`: shared types, `name_key` (the uniqueness key of deck and tag names; `deck_name_key` is an alias), and the length limits shared by the store and the import (`MAX_DECK_NAME_BYTES`, `MAX_CARD_SIDE_BYTES`, `deck_name_fits`, `card_side_fits`, `CardSide`; ADR 0018): `Deck`, `DeckSummary` (deck + new/due counts), `Card`, `Grade` (Fail/Pass), `ReviewEvent` (one log entry, with `EventKind`: `Review(Grade)`, `Reset` or `Undo { undoes }`, ADR 0028), `Phase`, `CardState` (`New` or `Scheduled(Schedule)`), `Settings` with its defaults, ranges and `check_*` functions (`domain/settings.rs`, ADR 0027), and `Tag` with `check_tag_name` and `MAX_TAG_NAME_BYTES` (`domain/tag.rs`, ADR 0029).
- `src/scheduling/`: FSRS scheduling (ADR 0006), using the `fsrs` crate.
  - `mod.rs`: `Scheduler` (desired retention, default FSRS-6 parameters; built per transaction from the stored retention by `storage::settings::scheduler_in`, ADR 0027). `schedule(card_id, state, grade, now)` gives the state after one review; `rebuild_state(card_id, events)` replays a card's log: `surviving` drops undos and the entries they cancel and orders the rest, then reviews fold `schedule` and a reset gives New (ADR 0028). 10-minute step for new and failed cards; elapsed days are rounded 24-hour periods. A Pass on a review card is at least elapsed + 1 days, before and after fuzz (ADR 0009).
  - `fuzz.rs`: deterministic interval fuzz (Anki's ranges, seeded from card id + review count).
  - `session.rs`: the study session, pure (no SQL, no clock): `StudyInput`, `interleave` (new cards spread evenly among reviews), `Session` (`next(now)`: due step cards, then the queue, then step cards up to 20 minutes early; `graded` re-queues cards left in the 10-minute step), `Summary`, `capped` (60 s), `allowance` (what is left of a daily limit). The module is crate-private; `scheduling` re-exports what the app uses (`StudyInput`, `Due`, `Session`, `Summary`, `capped`). Tests in `session/tests.rs`. See ADR 0014.
  - `tests.rs`: FSRS reference values and property tests (rebuild = review-by-review; with undos and resets, rebuild = the fold of the counted reviews, #11).
- `src/content/`: card Markdown → `Document`, a UI-agnostic block/inline tree, with `pulldown-cmark` (ADR 0019). No UI.
  - `mod.rs`: the tree (`Document`, `Block`, `Inline`, `ImageTarget`, `Align`) and `MAX_DEPTH` (16), the nesting cap.
  - `parse.rs`: `parse(md)`, a stack of open containers over the parser's events. Raw HTML becomes literal text, NUL becomes U+FFFD, `$$…$$` alone in a paragraph becomes a `DisplayMath` block, inline math closed by a `$` followed by a digit is text (`$5-$10`), and containers past the cap are flattened into the deepest one.
  - `plain.rs`: `plain_text` (no syntax, for screen readers) and `plain_summary` (one line, at most `PREVIEW_CHARS` = 200 characters, from the first 16 KiB, for the card list) and `one_line_summary` (the same from a `plain_text`).
  - `tests.rs`: each construct, untrusted HTML, dollars, the cap, property tests (never panics, within the cap), and 1 MiB hostile sides (`hostile_sides`) and random syntax repeated to 256 KiB, parsed within a time bound on a small stack, with node and text counts bounded by the input (ADR 0025).
- `src/interchange/`: export and import of the whole database as a `.rappel` file (ADR 0017; ADR 0020 for `.cards`, which still imports). No UI.
  - `mod.rs`: the public types (`ExportSummary`, `ImportPlan` and its `ImportSummary` with `TableCounts` and `Conflict`s, `ImportReport`, `ImportProblem` / `FieldProblem` for a refused file) and the internal `Limits` (file, JSON, text sizes).
  - `format.rs`: the serde types of `cards.json` (`FORMAT_VERSION` 2), fields in file order, unknown fields denied: decks, cards, tags, card tags, log entries (`kind`, `grade`, `undoes`) and the typed `SettingsRecord`. Version 1 (`EARLY_TEST_VERSION`) is refused, not read (ADR 0017).
  - `archive.rs`: writes the zip deterministically (`cards.json` then `media/`, fixed timestamp and permissions) and reads `cards.json` back after checking the entries are exactly those two (names compared as bytes, the count checked against the end record, entries that do not overlap, a size cap on decompression).
  - `validate.rs`: the checks that need no database, one function per table in file order (top level, decks, cards, tags, card tags, review events, settings), so the first broken rule is the one reported: version first, then ids (`id::is_uuid_v7`), uniqueness, references, kinds and the fields each kind allows, undo targets, grades, timestamps, names, text sizes, NUL characters in names and card sides, commas in tag names, live cards in deleted decks, setting ranges.
  - `export.rs`: `Store::export_to` (atomic write, mode `0600`) and `export_bytes_at`, reading every table and the stored settings in one read transaction, sorted by id.
  - `import.rs`: `Store::plan_import` (a regular file only, `NotAFile` otherwise; each buffer dropped once the next is made; read and compare, no writes) and `Store::apply_import` (no-op if nothing is new or revived; else backup, then one transaction that compares again, revives deleted decks and cards that are live in the file and the cards deleted with a revived deck, inserts, replaces the settings when the plan applies them (only into a database without decks), and rebuilds the schedule of cards with new entries via `storage::rebuild_cards`). Tags and card tags merge by id, and a file tag with the name key of a database tag (another id) is mapped onto it (`Classified::mapped_tags`), its card tags attached to the database's id; a tag renamed under the same id and a second undo of one entry are conflicts.
  - `tests/`: `mod.rs` holds the shared fixture and helpers; `format.rs` (a fixed fixture that pins the format), `round_trip.rs`, `revive.rs` (merges, reviving deleted rows), `conflicts.rs`, `concurrent.rs` (the second connection: an export beside an open write, an import beside an open reader, a plan made stale by the main store, the worker types being `Send`), `refused.rs` (malformed and tampered files, special files), `fuzz.rs` (lying zip headers, damaged and random bytes, zip tricks, random and damaged JSON: refused or harmless, within a time bound, never quoting the file), `property.rs` (random databases), `large.rs` (larger data; the pre-rename `.cards` export is refused by its version), `settings.rs` (settings in the export, applied or kept), `log_and_tags.rs` (version 2's entries and tags: refusals, conflicts, merges).
- `src/storage/`: SQLite storage (ADR 0005).
  - `mod.rs`: `Store::open_concurrent(data_dir)` opens a second connection to a database `Store::open` already opened, for a worker thread: it never creates the file, runs no check, backup or migration, and refuses a schema that is not the latest (ADR 0018). `Store::open(data_dir)` opens `<data_dir>/rappel.sqlite3` in named steps: `connect`, the integrity and version checks, `apply_write_settings` (WAL, `synchronous=FULL`, foreign keys), `back_up`, then the migrations. A failed daily backup or prune does not stop it. It is kept as an `OpenWarning` for `take_open_warnings`. `Store` owns the connection, an `IdGen` and its backup directory (`None` for in-memory test stores; `interchange` uses it to back up before an import). `observe_max_id` raises the generator above a table's largest id before each write that issues one.
  - `decks.rs`: `create_deck`, `rename_deck` (trimmed, at most 1 KiB, no NUL, unique among live decks), `list_decks(now, day_start)` (each deck's new and due counts are the lengths of its `study_input`, so the deck list and the deck page agree), `decks` and `deck(id)` (live decks without counts, one query), `delete_deck` (soft; the deck and its live cards share one `deleted_at`), `undelete_deck` (brings back exactly that batch, ADR 0012).
  - `cards.rs`: `add_card`, `edit_card` (returns the stored card; each side at most 1 MiB, no NUL), `card`, `list_cards`, `delete_card` (soft), `undelete_card` (refused while the card's deck is deleted, ADR 0013).
  - `review.rs`: `record_review(.., now)` (event + cache in one transaction, time `max(now, last entry)`), `reset_card(.., now)` (a reset entry, the card new again) and `undo(card, entry, now)` (only the latest surviving review or reset; an undo entry, then the card rebuilt from its log), ADR 0028, `study_input(deck, now, day_start)` (due reviews cut to what `max_reviews_per_day` still allows, step cards due within 20 minutes and never limited, new cards first reviewed since `day_start`, older cards reviewed since then (`reviews_today`; both count only reviews that are not undone, since the card's last reset, the `COUNTED_REVIEWS` table), and today's remaining new cards up to `max_new_per_day`; the limits are read from the settings in the same transaction; `study_input_in` is the same on a connection inside a read transaction, shared with `list_decks`), `next_study_change(deck, now)` (the next time `study_input` would offer one more card: a review's due time, or a step card's due time minus 20 minutes).
  - Every public write that issues an id or a timestamp has a private `*_at(now)` twin for tests, except `record_review`, `reset_card` and `undo`, which take `now` themselves (ADR 0014, 0028); `remove_tag` needs no time; `decks/`, `cards/`, `review/` hold their `tests.rs` (the review one has the cache-equals-rebuild property test). Deleted rows are hidden from every deck, card and queue operation; a deleted card's history and cache stay readable by card id (`review_events`, `card_state`) (ADR 0008).
  - `migrations/`: `MIGRATIONS` (numbered `NNNN_*.sql` files embedded with `include_str!`) and `migrate`. A migration may also have a Rust `backfill` step (run after its SQL, in its transaction) and ask for a schedule cache rebuild. Merged migrations are hash-pinned by a test.
  - `backup.rs`: online-backup copies into `<data_dir>/backups/` (`backups_to_keep` is the pure retention rule, `prune_backups` applies it; ADR 0026), in one step so writes from another connection cannot restart it, and the public `list_backups` (newest first, as `BackupInfo`).
  - `restore.rs`: `restore_backup` validates a copy of a backup (and migrates it there if it is older), moves the current database and its sidecar files aside to `rappel.sqlite3.replaced-…`, installs the copy and opens it with `Store::open` (ADR 0007), protecting the restored backup from the prune that open does. `move_aside` first writes the chosen name to `rappel.sqlite3.moving-aside`, so a retry after a crash fills the same set (ADR 0026). `finish_restore` installs the copy an interrupted restore left waiting, after checking it again, when its backup is gone (`NoRestoreWaiting` without one). `start_fresh` moves them aside the same way and opens a new, empty database; it refuses while an interrupted restore's copy waits (ADR 0016). `Store::open` refuses to start an empty database when the main file is missing but a `-wal`/`-journal` (`OrphanedSidecar`) or an interrupted restore's copy (`InterruptedRestore`) is there.
  - `tags.rs`: `tags`, `card_tags`, `add_tag` (finds the tag by name key or creates it) and `remove_tag` (the link only; tags are never deleted), ADR 0029. Tests in `tags/tests.rs`.
  - `settings.rs`: `Store::settings` and the setters `set_max_new_per_day`, `set_max_reviews_per_day`, `set_day_start_hour` (each checks its value first) and `set_desired_retention`, which writes the value and rebuilds the whole schedule cache in one transaction (nothing if unchanged). `settings_in` reads the table (defaults for missing keys, also before the table exists, so a migration's rebuild works); `stored_settings` / `replace_settings` read and replace only the stored keys, for export and import; `scheduler_in` builds the `Scheduler` from it inside the caller's transaction (ADR 0027). `backup_dir(data_dir)` (in `mod.rs`) is where the app finds the backups.
  - `schedule.rs`: `Store::review_events` (the whole log, every kind), `Store::card_state` (reads the `card_schedule` cache) and `Store::rebuild_schedule_cache`; `insert_event`, how the store appends an entry; reading a log from before migration 0007 too (every row a review), for the migrations that rebuild before it; `rebuild_cards` (some cards only, in the caller's transaction, for an import); `upsert_schedule` / `write_card_state`, the one way cache rows are written. A migration with `rebuild_schedule: true` rebuilds the cache inside its own transaction, with the stored retention.
  - `restore/tests.rs`: restore tests (v1 and v2 backups, interrupted restores, refusals that change nothing).
  - `settings/tests.rs`: defaults, persistence, refused values, bad stored values, the retention change equal to a replay (also as a property), a failed rebuild changing nothing, other connections using the stored retention.
  - `tests/`: store-level tests, by topic: `fresh.rs`, `reopen.rs`, `migrations.rs`, `integrity.rs`, `schema_rules.rs`, `cache.rs`, `perf.rs` (time bounds at 5,000 cards with 2,000 due, ADR 0025); `mod.rs` holds the helpers and fake migrations the restore tests share.

  The schema is in `migrations/0001_initial.sql`; `0002_card_schedule_phase.sql` reshapes the `card_schedule` cache (adds `phase`); `0003_soft_delete.sql` adds `deleted_at` to `decks` and `cards` and the live-unique deck name index. `0004_deck_name_key.sql` moves that uniqueness onto `decks.name_key` (NFC + lowercase, filled in by the migration's Rust backfill step, ADR 0010). `0005_rebuild_for_interval_floor.sql` only rebuilds the schedule cache after the scheduler change of ADR 0009. `0006_settings.sql` adds the empty `settings` table (ADR 0027). `0007_log_entry_kinds.sql` rebuilds `review_events` with `kind` and `undoes`, their CHECKs, a unique index on `undoes` and a trigger on undo targets (ADR 0028). `0008_tags.sql` adds `tags` and `card_tags` (ADR 0029).
- `tests/import_memory.rs`: an integration test binary of its own, so nothing runs beside it: the peak memory of planning an import, from `/proc/self/status`, held within 1 GiB at the limits (Linux only, ADR 0025).
- `examples/fill_scratch_db.rs`: fills a scratch data directory with one deck of many cards (default 5,000; none with 0) through the public `Store` API, to check the card list's speed. With `--due N`, the first N cards get a past review history (recorded with `record_review` at past times) so they are due now. With `--markdown`, it also adds a deck of 20 new cards, one per Markdown construct (ADR 0019). With `--math`, a "Math" deck: the 15 formulas of the ADR 0021 spike, one per card, and a card with invalid LaTeX. It refuses the app's own release and debug data directories and any path with `..`.

### `rappel` today

- `src/main.rs`: sets up `tracing` (level from `RUST_LOG`), registers the embedded gresource, creates the `adw::Application`. `data/style.css` (table borders and the sideways-scroll hint of wide formulas) is loaded by `AdwApplication` itself from the resource base path. The first `activate` runs `startup::start` and shows the main page or the page for the problem. Later activations only present the window. The database is opened there and not in `main()`, so a second launch, which only forwards `activate`, never opens it (ADR 0011).
- `src/state.rs`: `AppState`, a cheap-to-clone `Rc<RefCell<Store>>` handle and the UI's only way to the database. No method holds a borrow past its return. `settings` and the setters for the limits and the day start (`next_day_start` and the day start for `list_decks` / `study_input` read the hour from them), `backup_dir`. The associated functions `list_backups`, `restore_unopened`, `finish_restore_unopened` and `start_fresh_unopened` serve the recovery page, which runs before any database is open. `export_on_worker`, `plan_import_on_worker`, `apply_import_on_worker` and `set_desired_retention_on_worker` are associated functions too: they run on a worker thread, each on its own connection (`Store::open_concurrent`, ADR 0018).
- `src/clock.rs`: `day_start_ms` (the settings' day start hour, local, of the current study day, computed with GLib's time zones; a skipped hour begins the day an hour later, a repeated one takes the later time; tested for every hour across the DST days of three zones), `next_day_start_ms` (that hour of the next calendar day), and their `local_*` forms. Core gets the result as a timestamp (ADR 0014, 0027).
- `src/startup.rs`: resolves and creates the data directory, opens `AppState`, and maps a failure to a `Problem` (recovery, too new, other), unit-tested and without GTK. `data_folder_line` is the "Data folder: …" line the problem pages show, and `too_new_text` the "too new" page's description.
- `src/transfer/`: Export… and Import… from the primary menu (ADR 0018).
  - `mod.rs`: the `GtkFileDialog`s, the workers (`ui::worker`), the import dialog (`data/import_dialog.blp`: Import Data? / Cannot Import / Nothing to Import) and the toasts.
  - `text.rs`: the texts (`export_file_name`, `exported_text`, `plan_view`, `conflicts_text`, `imported_text`, `short_front`), including new tags, card tags, settings applied or kept, and the tag and undo conflicts. Pure and unit-tested.
  - `names.rs`: `Names`, the user's own deck names and card fronts (their plain summary) that conflicts refer to, never the file's text.
- `src/render/`: a `Document` → GTK widgets, with libadwaita style classes only (ADR 0019). The one place where widgets are built from data in Rust.
  - `mod.rs`: `render(doc)`, a vertical box with one widget per block (at most 2,000 widgets, then plain text). Labels are wrapping, not selectable, so the focus stays on the review page. `fill` / `clear` replace or empty a box's rendered content (review page and editor preview). `shown_part` keeps at most `MAX_SHOWN_BYTES` (32 KiB) of a side, cut after a paragraph, for both of them: Pango's first layout of a longer paragraph freezes the window (ADR 0025). Links show their URL as a tooltip (`query-tooltip` → Pango layout index).
  - `breaks.rs`: `Runs` / `breakable` give every label's text a zero-width space after each 64 characters without a breaking space, only between grapheme clusters (`unicode-segmentation`), because a wrapping label's first measure grows with the square of its longest unbroken run (ADR 0025). The markup counts runs across tags. `accessible_text` takes the breaks out again.
  - `markup.rs`: `inline_markup(inlines, budget)`, inlines → Pango markup with every piece of card text escaped and only our own tags (no `<a>`), plus each link's byte range and each drawn formula's placeholder (U+FFFC) index; `link_at`. Pure and unit-tested (Pango parses every result).
  - `math.rs`: LaTeX → RaTeX display list, pure (ADR 0021, 0023). `lay_out` (source over 4 KiB is not parsed, a layout over `MAX_EM` = 128 em or RaTeX's own limit is `TooLarge`, a panic inside RaTeX is a parse failure), the bounded `formula` cache (800 entries, keyed by source, style and colour), `Budget::place` (at most 200 formulas per side: `Formula`, `ErrorSource` or `Source`), and the font-size and pixel helpers. Unit-tested with the spike's formulas, invalid and hostile input.
  - `math_view.rs`: `MathView`, one formula drawn with `Snapshot::append_cairo` and `ratex_cairo`, in the widget's CSS `color` (live on a theme switch). Accessible role Math, label the LaTeX source. Not focusable.
  - `math_paragraph.rs`: `MathParagraph`, text with formulas in it: Pango lays the text out with an `AttrShape` box per formula so each sits on the text baseline; each formula is a `MathView` in a horizontal scroller without a scrollbar (`render::inline_math_scroller`, ADR 0024) put where Pango put its box, as wide as the formula and never wider than the line. Used for paragraphs, headings and table cells that have a drawn formula; others stay `GtkLabel`s.
  - `style.rs`: the pure decisions: `back_shown`, `heading_class`, `list_marker`, `table_cell_classes` (borders and header row of a table cell), `widget_cost`. Every side is laid out the same way. Unit-tested.
- `src/window.rs`: `RappelWindow`, an `adw::ApplicationWindow` subclass using a composite template. It holds the `AppState` (`OnceCell`, set once). `show_main` turns open warnings into toasts and shows the main page; `show_problem` shows a startup problem page. It owns `win.export` / `win.import` (one job at a time, holding the application while it runs), `win.preferences` and `data_changed`, which reloads the deck list and every deck page in the navigation stack after an import. Its `close_request` looks through the open dialogs for a `CardEditor` with unsaved text and asks its "Discard Changes?" first, as Escape does.
- `src/ui/`: small helpers shared by pages, dialogs and rows; no layouts. Use them instead of writing a local copy.
  - `toast.rs`: `persistent_toast` (plain text, stays until dismissed), `info_toast` (plain text, goes away by itself), `show_toast_from` (the overlay around a widget, or the window's own; this is the one place `ui` reaches `RappelWindow`), `log_failure` / `show_error` (a generic warning in the log, the message with user content only at debug level, SPEC §2), `ErrorSlot` (an error toast that replaces the slot's previous one), `undo_toast` (High priority, "_Undo"), and `warning_message` (the toast text for an `OpenWarning`). Every error toast goes through `show_error` or `ErrorSlot`, except the recovery page's, which log their errors in full at warning and error level: they come before any database is open, never hold card or deck text, and the paths make the data folder fixable (ADR 0025, row 13); the card editor passes its own overlay, since the dialog covers the window's.
  - `dialog.rs`: `builder` / `object` / `alert` load objects from the bundled `.ui` files (the resource prefix is in one place) and log a missing object.
  - `nav.rs`: `navigation_view` (the ancestor `AdwNavigationView`, logged if missing) and `pop`. Its module comment records the focus rule: focus a pushed page in its `shown` handler.
  - `rows.rs`: `install_id_action` (a page action taking an id string), `forward_id` (a row's `row.*` action forwarding to it), `label_menu_button` ("Actions for …").
  - `focus.rs`: `index_after_removal`, the row to focus after a removal (or `None`: the empty state's button). Pure and unit-tested.
  - `text.rs`: `group_digits` ("5,210"), `count` ("1 deck", "2 decks") and `decks_cards_reviews` ("12 decks, 840 cards and 5,210 reviews"). Pure and unit-tested.
  - `debounce.rs`: `Debounce`, which runs a closure once input pauses (a new `restart` drops the waiting run); used by the editor's preview and the deck page's study re-check.
  - `worker.rs`: `run`, which runs blocking work (export, import, restore, finish restore, start fresh) on GIO's thread pool, holding the application only while it runs, and returns `Panicked` if it panicked.
  - `callback.rs`: `Callback`, a shared closure that template structs can derive `Debug` with.
  - `mod.rs`: `init_once`, which sets a `OnceCell` of a widget under construction and logs instead of ignoring a second set.
- `src/pages/recovery_page.rs`: `RecoveryPage` explains why a backup is needed, lists backups newest first (one `BackupRow` each), confirms with an `AdwAlertDialog` (`data/restore_dialog.blp`) and restores on a worker thread. With no backups (and no interrupted restore's copy waiting) it offers Start Fresh instead (`data/start_fresh_dialog.blp`, ADR 0016). While an interrupted restore's copy waits it offers Finish Restore (pure `offers_finish_restore`; no confirmation, nothing is deleted; ADR 0026). Its callback says how the database was obtained (`Recovered::Backup` / `Finished` / `Fresh`), for the window's toast.
- `src/pages/decks_page.rs`: `DecksPage`, the root `AdwNavigationPage`. Its header bar holds the primary menu (Export…, Import…, Preferences; F10). It shows the deck list (or the "No Decks Yet" empty state) and handles create, rename, and delete with an Undo toast, through `AppState`. Its class actions `decks.rename` / `decks.delete` take a deck id. Activating a deck pushes its `DeckPage`, unless a deck page is already on top (key repeat, #20); coming back reloads the counts. See ADR 0012.
- `src/pages/deck_page.rs`: `DeckPage`, one deck's `AdwNavigationPage`, built per open. Its cards are a `GtkListView` over a `gio::ListStore` of `CardObject` in creation order, updated item by item (add, edit, delete, Undo). `reload` reads the cards again (after an import). Class actions `deck.new-card`, `deck.study`, `deck.edit-card` / `deck.delete-card` (card id). Its subtitle says what there is to study, and Study is disabled when that is nothing. A `Debounce` re-checks this when the next card becomes due or the next study day begins (capped at one hour per wait). See ADR 0013, 0014.
- `src/pages/review_page.rs`: `ReviewPage`, a pushed study session: front, Show Answer, then Fail / Pass, and a summary at the end. Both sides are parsed and rendered with `render` (the back at the reveal), at most 32 KiB of each (`render::shown_part`); a cut side shows a note under the card (the pure `cut_note_shown`). An empty back shows only the grade buttons. The card area's accessible label and description are the sides' plain text, with the note when cut (`with_cut_note`). Keys in the bubble phase (Space/Enter reveal; 1 Fail; 2 or Space Pass; E edit), decided by the pure `key_action`. Edit (E, and a header button) opens the deck page's `CardEditor` on the card on screen; a save re-renders it in place without touching the reveal, the timers or the session, and is passed on to the deck page's list; closing without saving changes nothing. Each answer goes through `record_review` at once. Pure text helpers `summary_text`, `duration_text` are unit-tested. See ADR 0014.
- `src/widgets/` holds the row widgets (each with a `data/*.blp` layout) and `CardObject` (a list item, no layout).
- `src/widgets/card_object.rs`: `CardObject`, a list item holding a `Card` and its one-line preview (`content::plain_summary` of the front).
- `src/widgets/card_row.rs`: `CardRow`, the recycled row widget (preview label and a menu); `bind`/`unbind` point it at a card, and its `row.*` actions forward to the page.
- `src/widgets/deck_row.rs`: `DeckRow`, an `AdwActionRow` with the name, the new/due counts and a menu. Its `row.*` actions forward to the page with the row's deck id.
- `src/widgets/backup_row.rs`: `BackupRow`, an `AdwActionRow` with a backup's time and size and a Restore button, which the recovery page connects.
- `src/dialogs/card_editor/`: the card editor (ADR 0022).
  - `mod.rs`: `CardEditor`, an `AdwDialog` with front and back in `GtkSourceView`, each in a `GtkFrame` (Markdown highlighting, monospace, wrapping; the Adwaita or Adwaita-dark scheme following `AdwStyleManager`, pure `scheme_id`). A live preview renders both sides with `render`, like the review page, 250 ms after typing pauses (`ui::debounce`) and only while its header toggle is on; it renders at most 32 KiB of each side (`render::shown_part`) and says so when it cuts. Beside the sources when wide, below them under 720 sp (an `AdwBreakpoint`). Ctrl+Enter saves, Ctrl+Shift+Enter saves and starts a new card; Ctrl+B / Ctrl+I wrap the focused side's selection, as one undoable step. A blank front or a side over 1 MiB disables saving (the pure `check_card`; the length error shows under that side); closing with changes asks first (`data/discard_dialog.blp`). Reports each save to the deck page as `Saved`. `CardEditor::open` is how the deck and review pages open it: one editor at a time (their `editing` flag), cleared on close before their `on_closed` sets the focus.
  - `format.rs`: `wrap`, the text Ctrl+B / Ctrl+I put in place of a selection, and what to select after. Pure and unit-tested.
- `src/dialogs/preferences.rs`: Preferences (Ctrl+, / primary menu, `win.preferences`), an `AdwPreferencesDialog` loaded from `data/preferences_dialog.blp`. The two limits and the day start save as they change (a failed write shows a toast and the stored values again); Desired Retention opens an `AdwAlertDialog` (`data/retention_dialog.blp`) that says due dates will change, then rebuilds on a worker thread with the dialog unable to close; Errors go through an `ErrorSlot` into the dialog's own toast overlay (`ErrorSlot::show_in_preferences`). Open Backup Folder creates the folder if needed and opens it with `GtkFileLauncher`. After a change, closing the dialog calls `RappelWindow::data_changed`. The conversions (`percent_from_retention`, `retention_from_percent`, `limit_from_value`, `hour_label`, …) are pure and unit-tested; a GTK test loads the layouts and drives the rows.
- `src/dialogs/deck_name_dialog.rs`: the create/rename `AdwAlertDialog` (`ask`). Its pure name check `check_deck_name` (empty / too long / duplicate by `deck_name_key` / valid) and `name_error` give the inline error.
- `data/window.blp`: `AdwToastOverlay` around a `GtkStack` with the pages `main` (an `AdwNavigationView` holding `DecksPage`), `recovery`, `too-new` and `error`, each with its own header bar. The window action `win.new-deck` opens the name dialog; `win.new` (Ctrl+N) opens the card editor on a deck page and the name dialog on the deck list, and does nothing on the review page. ## UI build pipeline

UI layout is written in Blueprint, never in Rust code or hand-written `.ui` XML.

```
data/*.blp ──blueprint-compiler──▶ $OUT_DIR/ui/*.ui ──glib-compile-resources──▶ $OUT_DIR/rappel.gresource
                                                                                  │
                                         gio::resources_register_include! ◀───────┘ (embedded in the binary)
```

`crates/app/build.rs` drives both steps; `data/resources.gresource.xml` lists the files under the resource prefix `/io/github/rsmirke/Rappel/`. Widgets load their template with `#[template(resource = "/io/github/rsmirke/Rappel/<name>.ui")]`.

## Quality gate

`scripts/check.sh` runs `cargo fmt --all --check`, `cargo clippy --workspace --all-targets --locked -- -D warnings` (with `clippy::pedantic`, `unwrap_used`, `expect_used`, and `allow_attributes` / `allow_attributes_without_reason`: a lint is silenced only by `#[expect(.., reason = "..")]`, which fails the build once it is no longer needed), `cargo test --workspace --locked` and `cargo deny --locked check -D license-exception-not-encountered` (licences compatible with GPL-3.0-or-later, RustSec advisories, crates.io only; the `-D` makes an unused licence exception an error, so a changed `OFL.txt` hash for the KaTeX fonts cannot pass silently, ADR 0023). `third_party/` (vendored code, ADR 0021) is a workspace `exclude`, so none of these steps checks it. `scripts/pre-commit.sh` refuses commits on `main` and then runs the gate; `scripts/install-hooks.sh` installs it. `.github/workflows/ci.yml` runs the same `scripts/check.sh`, under Xvfb (`xvfb-run -a`), on every pull request and on pushes to `main`, in an `ubuntu:26.04` container with the README's system packages and stable Rust (see ADR 0003). Some tests start GTK, so the gate needs a display (ADR 0024). They go through `crates/app/src/testing.rs` (test builds only): one thread owns GLib's default main context and runs their bodies one at a time, because `gtk::init` keeps that context for good. `testing::within` (and `within_stack`, with a stack size of its own) runs a test's work on `SMALL_STACK` with a time bound, as `rappel-core`'s `test_support::within` does; `RAPPEL_TIMINGS=1` makes them and `print_timing` print the times.
